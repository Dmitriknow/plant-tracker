# Инструкция: метод нейминга контекста для Obsidian vault

> Скорми этот текст агенту как инструкцию. Он само-достаточный: агент сможет работать с vault, соблюдая наши конвенции.

---

Ты работаешь с персональным Obsidian vault пользователя. Ниже полный метод организации контекста. Соблюдай его строго.

## Трёхслойная архитектура

```
vault_root/
├── _schema.md              ← схема vault (структура, конвенции)
├── _index.md               ← каталог всех wiki-страниц
├── _log.md                 ← хронология всех операций
│
├── raw/                    ← неизменяемые исходники (транскрипты, статьи)
│   └── sessions/
│
├── wiki/                   ← скомпилированное знание (пишет LLM)
│   ├── <Domain>/           ← папки по доменам (F26 Fall Lab, Work, Personal...)
│   │   ├── Sessions/
│   │   ├── Entities/
│   │   └── ...
│   └── Profile/
│
└── _templates/             ← шаблоны заметок
```

**raw/** — исходники. Однажды записан, никогда не редактируется.
**wiki/** — заметки, которые ты создаёшь и поддерживаешь.
**_schema.md** — правило, по которому ты работаешь.

## Правило нейминга файлов

Формат: `{категория}.{имя}.{дата}.md`

| Категория | Для чего | Пример |
|-----------|----------|--------|
| `transcript` | Исходные транскрипты | `transcript.2026-11-07.f26-intro.md` |
| `session` | Саммари сессий (wiki) | `session.2026-11-07.intro-call.md` |
| `chat` | Логи чатов | `chat.2026-11-07.f26-intro.md` |
| `person` | Люди/сущности | `person.alexander-povalyaev.md` |
| `profile` | Профиль пользователя | `profile.dima.md` |
| `work` | Рабочие проекты | `work.vizavi-ceramica.md` |
| `plant` | Растения | `plant.monstera.md` |
| `dance` | Танцы | `dance.lindy-hop.md` |
| `media` | Доrамы/фильмы | `media.squid-game.md` |

**Системные файлы** — префикс `_`: `_schema.md`, `_index.md`, `_log.md`.
**Шаблоны** — в `_templates/` без префикса.

## Правила нейминга

1. Имя — **kebab-case** (латиница, дефисы).
2. Дата — **ISO** `YYYY-MM-DD` (алфавитная сортировка = хронологическая).
3. Категория — всегда первой (это ключ для быстрого поиска).
4. Нет даты — опусти сегмент `.дата`.
5. Новая категория — добавляй при необходимости и **дописывай её в `_schema.md`**.

## Фронтматер

Каждая заметка wiki начинается с:

```yaml
---
title: "Заголовок"
type: session | entity | person | profile | concept
date: YYYY-MM-DD
tags: [tag1, tag2]
sources: [raw/path/to/source.md]   # только для сессий
---
```

## Воркфлоу

### Ingest (новый источник)
1. Сохрани исходник в `raw/` по категории.
2. Прочитай, выдели ключевые люди/концепты.
3. Напиши саммари в `wiki/`, обнови или создай entity-страницы.
4. Обнови `_index.md` (добавь страницу в каталог).
5. Допиши запись в `_log.md` с датой.

### Поиск
1. Сначала `_index.md` — найди релевантные страницы.
2. Читай нужные страницы, синтезируй ответ.
3. Ценный ответ — сохрани как новую страницу wiki.

### Lint (периодический аудит)
Проверяй: битые ссылки, осиротевшие страницы (без входящих ссылок), устаревшие утверждения, пробелы знаний.

## Языковое правило

- **Заголовки, названия, описания, теги, папки** → английский.
- **Длинный контент, теряющий смысл при переводе** (транскрипты, специфическая терминология) → оригинальный язык.
- Применяй к каждой части заметки независимо: название на английском + тело на русском — нормально.

## Связи

Используй вики-ссылки `[[имя.файла]]` для связывания связанных заметок. `_index.md` — место для каталога всех страниц.

## Шаблоны

Если в `_templates/` есть шаблон нужного типа — используй его как основу для новых заметок.
