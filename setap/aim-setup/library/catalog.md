# catalog · нужда → инструмент

Карта большой системы: что можно поставить под дело. Всё сразу не ставится – комплект собирается по интервью; не хватило по ходу – предложи и добавь.

Одна нужда – один инструмент. Если нужда появилась посреди работы, а инструмента нет в комплекте, – предложи его одной строкой; после «да» возьми из `library/` и запиши в `context/kit.md`.

| нужда | инструмент |
|---|---|
| описать результат проекта: для кого, что меняется, критерии успеха | `library/vision.md` |
| уточнить задачу до работы:
 агент расспрашивает, пока постановка не станет полной | `grill-me` |
| собрать план, разбить на шаги | `make-plan` |
| проверить план или результат со стороны | `second-look` |
| посмотреть, как это выглядит на самом деле, и показать ссылкой | `look` |
| нажать, ввести, повернуть, прочитать ошибки страницы – в настоящем браузере, экраном телефона | `browser` |
| вести документацию и память проекта | `update-docs` + агент `docs-updater` |
| разобраться в теме до работы | `research` |
| новая логика, правила, обработка данных | `tdd` |
| сломалось, работает не так | `bugfix` |
| выложить черновик наружу и проверить живой адрес | `deploy-verify` |
| выпустить к людям: проверка до и после выпуска, рецепт выпуска | `ship` |
| закончить вечер: ничего не осталось несохранённым, серверы погашены | `wrap-up` |
| застрял, выбор подхода не складывается, разобрать до основ | `first-principles` |
| вести вторую сессию параллельно: логика в одной, облик в другой (ставить не нужно – агент читает файл) | `parallel` |
| продолжить проект, который уже есть (ставить не нужно – агент читает файл) | `own-project` |
| разделить рабочее и личное, понять, что агенту нельзя видеть | `library/boundaries.md` |
| собрать файл о себе, чтобы агент меньше переспрашивал (ставить не нужно) | `self-interview` |
| назвать заметки и встречи так, чтобы агент их находил | `library/naming.md` |
| зарегистрироваться в стороннем сервисе – браузер подсказывает шаги, ключ кладёт человек (необязательно) | `aside` |

Карта растёт вместе с модулем: свои скиллы приходят ко второй среде, проверки-хуки – к третьей, выкладка людям – к четвёртой.

Ставить – копированием папки в `.claude/skills/<имя>/`, `.agents/skills/<имя>/` и `.opencode/skill/<имя>/`; работать можно сразу, читая `SKILL.md` напрямую, даже если агент ещё не подхватил скилл в списке. Агенты – в `.claude/agents/` (Claude Code); если у агента нет этого субагента – свежая сессия или его собственный субагент.
