# own-project · продолжаю свой проект

**Когда запускать:** `start` выяснил, что человек берёт проект, который уже есть. Файл читается прямо из `library/`, ставить его не нужно.

**Что должно получиться:** `project` в папке набора ведёт в папку проекта; агент знает правила проекта и может писать в него; проект запущен как есть, и в `context/project.md` записано, что уже работает. В коде проекта к этому моменту ничего не изменилось.

## шаг 1 · подключить папку

Нет `context/boundaries.md` – сначала вопрос 14 из `start`: до чтения проекта границы должны быть записаны. `project` уже ссылка на эту папку – шаг сделан, иди к проверке в конце шага.

Один вопрос, если путь ещё не назван: «где лежит проект?» Потом одно разрешение, отдельно от скана: «Подключу `<путь>` как `project/`: это ссылка, файлы останутся на месте. Прочитаю правила и код проекта; `.env`, ключи и данные не открываю. Можно?»

Проверь до ссылки:

- папка существует и это одна папка проекта, домашняя папка и `~/Developer` целиком не годятся;
- набор не лежит внутри проекта, а проект внутри набора. Claude Code читает `CLAUDE.md` из папок выше, и правила смешаются;
- `project` в наборе нет или это пустая папка. В ней есть файлы – остановись и спроси, что с ними делать; ничего не перезаписывай;
- путь без облака (признаки – в `start`). Проект в облаке – скажи одной строкой, решает человек.

Ссылка:

- мак, Linux: `rmdir project 2>/dev/null; ln -s "<полный путь>" project`;
- Windows, PowerShell: `New-Item -ItemType Junction -Path project -Target "<полный путь>"`;
- Windows, Git Bash (там работает Claude Code): `cmd //c mklink //J project "C:\путь\к\проекту"`.

На Windows пустую папку `project` сначала убери; режим разработчика для такой ссылки не нужен, диск должен быть локальным.

Доступ агента. Ссылка ведёт за пределы папки набора, поэтому агенту нужно разрешение на настоящий путь:

- Claude Code: запиши `.claude/settings.local.json` с `{"permissions":{"additionalDirectories":["<полный путь>"]}}` (файл уже есть – добавь строку, остальное не трогай). Заработает в новой сессии: скажи человеку закрыть агента, открыть папку набора заново и написать «продолжаем»;
- Codex: человек открывает сетап командой `codex --add-dir "<полный путь>"`. Постоянно – строка `writable_roots = ["<полный путь>"]` в разделе `[sandbox_workspace_write]` файла `.codex/config.toml` в папке сетапа, если папка доверенная;
- другой агент: скажи человеку одной строкой, что нужно разрешить запись в этот путь в настройках агента.

Проверь: `ls project/` показывает файлы проекта, и запись пробного файла `project/.aim/check` прошла. Удали пробный файл.

## шаг 2 · прочитать проект

1. `project/CLAUDE.md`, `project/AGENTS.md`, `project/README*`, манифест (`package.json` и похожие). Правила проекта действуют внутри `project/`; правила набора о секретах и трёх уровнях доверия сильнее правил проекта. Свои скиллы проекта – основные, библиотека добирает недостающее.
2. Запусти `bash checks/scan-keys.sh project` и покажи итог: только файл и строка, значения не показывай.
3. Посмотри имена правил в `project/.claude/settings.json` и `project/.codex/`: хуки и запреты проекта работают только из его собственной папки. Есть такие – скажи одной строкой, какие из папки сетапа не сработают, и предложи соблюдать их вручную.
4. Границы из `context/boundaries.md` действуют и здесь: данные клиентов и выгрузки в проекте не открывай.
5. Код читай столько, сколько нужно, чтобы описать проект. Описание покажи догадкой в 3–5 строк: что это, на чём, кто пользуется, где остановились.

## шаг 3 · git проекта

`git -C project status --short`, `git -C project log -5 --date=short --format='%ad %s'`, `git -C project branch --show-current`.

- **Git нет** – один вопрос: «завести git в проекте? Без него нет точек возврата». Нет – работаем без него, так и запиши в `PLAN.md`.
- **Есть незакоммиченное** – чужую работу не трогай. Один вопрос: «есть незакоммиченные правки в N файлах. Закоммитить их отдельным коммитом до начала или ты сделаешь сам?»
- **Ветка.** С «да» заведи рабочую ветку: `git -C project switch -c aim-<короткое имя>`. В основную ветку сливаем и пушим только с «да» на каждый раз. Над проектом работает кто-то ещё – спроси, как у них принято.
- **Проверка ключей.** `git -C project rev-parse --path-format=absolute --git-path hooks`. Там уже есть `pre-commit` или git берёт проверки из другой папки – не трогай их и не перезаписывай; перед каждым коммитом гоняй `bash checks/scan-keys.sh --staged project`. Файла `pre-commit` нет – с «да» поставь `checks/scan-keys.sh` как `pre-commit` по шагу 0 в `build`.
- **Служебная папка.** `.aim/` допиши в файл, который назовёт `git -C project rev-parse --path-format=absolute --git-path info/exclude`: так номера серверов не попадут в git, а `.gitignore` проекта останется как был.
- `.gitignore` проекта не заменяй. В нём нет `.env` – скажи одной строкой и предложи добавить.

## шаг 4 · запустить как есть

Запусти главный сценарий командами самого проекта, ничего не правя. Зависимости ставь только командой проекта по его lock-файлу (`npm ci` и похожие). Не запустилось – это факт для записи: чинить будем по плану.

Запиши в `context/project.md` раздел сразу после первого блока:

```markdown
## Что уже есть
- **Работает:** <что запускали и что увидели>
- **Как запустить:** <команда>
- **Сломано или не проверено:** <честно>
- **Кто уже пользуется:** <люди или «никто»>
- **Не трогать:** <что человек назвал>
```

Дальше вернись в `start`: вопросы об идеях пропусти, спрашивай только про следующий кусок. Что нужно, чтобы проект дошёл до людей? Что мешает? Что вообще нельзя менять? «Версия на четыре недели» – этот кусок, а не весь проект.

## в сборке

- В `build` не выполняй из шага 0: `git init`, создание `project/.gitignore`, настройку автора коммитов. Правило «папка внутри чужого репозитория» здесь не действует: это репозиторий человека.
- Правило про `project/site/` и заготовку через `npm create` не применяй: структуру проекта не меняй без шага в плане.
- Прогон из шага 4 – проверка на каждый шаг плана: то, что работало, должно работать и после шага.
- README и `docs/` проекта не заменяй шаблонами: дополняй существующее, новые файлы заводи только после «да».
- Выкладка: у проекта уже есть адрес и способ выкладки – используй их, каждая выкладка в живое – красный уровень, «да» на каждый раз.

## как отключить

Набор больше не нужен – удали только ссылку: `rm project` (без `/` на конце и без `-r`), в PowerShell – `(Get-Item project).Delete()`. Папка проекта останется на месте. Новая версия набора – перенеси ссылку вместе с `context/` и пропиши доступ заново по шагу 1.

## чего нельзя

- копировать проект в набор или перемещать его
- писать в проект до утверждённого плана (`docs/` и `.aim/` – можно)
- заменять или удалять чужие хуки, `.gitignore`, конфиги выкладки
- пушить, сливать в основную ветку, выкладывать без «да»
